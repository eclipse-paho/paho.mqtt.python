# Agent guidance for Eclipse Paho Python

## Contribution process

Before planning or implementing a contribution, read:
- CONTRIBUTING.md
- .github/pull_request_template.md
- README.md and documentation for the affected packages

Follow the contribution requirements in those files. In particular:
- Find or create an issue describing the change before opening a PR.
- For simple bug fixes, a PR may be opened once the issue exists.
- For larger changes, discuss the approach in the issue and reach
  agreement with maintainers before substantial implementation.
  Take account of agreement already recorded in the issue or task.
- Follow the contributor agreement and commit-author email requirements.
  Do not claim these requirements are satisfied without evidence.

For suspected security vulnerabilities, follow SECURITY.md, including
its requirement to use confidential reporting rather than public issues
or pull requests.

## AI-assisted contributions

Read and follow the Eclipse Foundation guidance:
- [Contributing Content Generated by an AI](https://www.eclipse.org/projects/handbook/#contributing-genai)
- [Disclosure](https://www.eclipse.org/projects/handbook/#genai-disclosure)

When preparing AI-assisted contributions:
- Disclose substantial AI assistance in the PR description, identifying
  the tool/model and the work it assisted with.
- Include an Assisted-by trailer in relevant commit messages, following
  the handbook's format:
  Assisted-by: [Provider] [Model-Family] ([Version/ID])
- Record known provider, model, and version details. Do not invent
  unavailable information.
- Follow the handbook's guidance on when disclosure is appropriate;
  trivial changes such as spelling corrections may not warrant it.
- For files largely or entirely generated by AI, follow the handbook's
  file-level disclosure and licensing guidance. Preserve existing
  notices and account for this project's dual licensing; do not copy
  the handbook's single-license example unchanged.
- Generated content must undergo the normal testing, security review,
  and intellectual property checks.
- Every commit must receive human review and approval before merge.
  Do not assert that human review occurred unless it actually did.

## Project structure

This is the Eclipse Paho MQTT v3.1/v3.1.1/v5 Python client.

The Python source code is located in src/paho.

## Implementation

- Keep changes focused on the issue being addressed.
- Preserve public API compatibility unless a breaking change is part
  of the agreed scope. Document any compatibility impact.
- Carefully consider QoS acknowledgements, packet identifier ownership,
  session persistence, and reconnect behavior when changing these paths.
- Follow existing code conventions and license headers, applying the
  AI disclosure guidance above where appropriate.
- Use a supported Python version.

## Validation

- Add or update tests for code changes; include a regression test for
  bug fixes where practical.
- Prefer the existing internal test servers for automated tests.
- Respect the formatting rules for Python files.
- Report the commands run, their results, and any checks that could
  not be completed.
- Documentation-only changes do not require running the Python test suite.

## Pull requests

- Use .github/pull_request_template.md.
- Reference the issue with "Closes #..." when fully resolved, or
  "Related to #..." otherwise.
- Explain the problem, the resulting behavior, compatibility impacts,
  and how the change was tested.
- Include the AI assistance disclosure described above when applicable.
- Follow the commit-message guidance in CONTRIBUTING.md.
